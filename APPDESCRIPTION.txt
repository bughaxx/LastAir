**Projet LastAir — état au 29 avril 2026**

LastAir est une app Android native Kotlin/Compose (package `com.bughaxx.lastair`, Material 3 Expressive, BOM 2026.03.01) sans Hilt. C'est un réseau social musical centré sur Last.fm. Auth en deux étapes : Google Sign-In (Credential Manager) + OAuth Last.fm. `AuthViewModel` est instancié dans `MainActivity` et passé à `AppNavigation`. Les autres ViewModels sont créés avec `viewModel()` dans leurs écrans. Navigation via `AppNavigation` avec `NavHost`. `AppNavigation` reçoit `authViewModel`, `deepLinkUri: Uri?` et `pendingRoute: String?` depuis `MainActivity`.

**Deep links et pending route** : `MainActivity` expose deux `mutableStateOf` : `deepLinkUri` (pour le callback OAuth Last.fm via `lastair://callback`) et `pendingRoute` (pour naviguer vers un écran depuis une notification). Les deux sont passés à `AppNavigation`. `onNewIntent` met à jour ces deux valeurs. Dans `AppNavigation`, deux `LaunchedEffect` consomment ces valeurs — celui de `pendingRoute` navigue puis appelle `onRouteConsumed()` (lambda passé depuis `MainActivity` qui remet `pendingRoute.value = null`).

**Architecture navigation** : `Box` racine contenant un `Scaffold` sans `bottomBar` + `AnimatedVisibility` pour la `AppBottomBar` flottante (align `BottomCenter`). La bottom bar se cache/montre via `bottomBarVisible: MutableState<Boolean>` piloté par un `NestedScrollConnection` (seuil ±50f). Le padding bottom du `NavHost` est animé avec `animateDpAsState` (cible `80.dp` quand visible, `0.dp` quand cachée, `tween(300)`) pour que le contenu suive l'animation de la navbar sans saccade.

**Écrans implémentés** : `LoginScreen`, `LastFmConnectScreen`, `HomeScreen` (2 pages : feed perso + feed amis), `Friends`, `Inbox`, `ShowAllScreen`, `Settings`, `Account` (ModalBottomSheet depuis HomeScreen, pas une route séparée — `Routes.ACCOUNT` supprimé).

**HomeScreen** : `HorizontalPager` + `SecondaryTabRow` en bas. Page 0 = 3 carousels (`HorizontalCenteredHeroCarousel` pour les tracks récents, `HorizontalUncontainedCarousel` pour top albums et top artists). Page 1 = feed amis via `FriendsActivityViewModel`. Roboto Flex variable déclarée au niveau fichier dans `HomeScreen.kt` comme `val robotoFlexVariable` — ne pas la redéclarer dans d'autres fichiers, l'importer directement depuis `com.bughaxx.lastair.ui.theme.robotoFlexVariable`.

**Covers et qualité d'image** : `ItunesHelper` (object, package `com.bughaxx.lastair`) expose trois méthodes suspend : `getHighQualityCover(artist, track, lastFmUrl)` pour les tracks (entity=song), `getAlbumCover(artist, album, lastFmUrl)` pour les albums (entity=album), `getArtistImage(artist, lastFmUrl)` pour les artistes (cherche une song de l'artiste, pas entity=musicArtist qui retourne des images noires). Toutes retournent des URLs `1200x1200bb`. iTunes est toujours tenté en premier — le fallback Last.fm n'est utilisé que si iTunes échoue. `isPlaceholder` détecte le hash Last.fm `2a96cbd8b46e442fc41c2b86b821562f`. Pour les covers manquantes/unreleased : `GenerativeCover` composable dans `HomeScreen.kt` génère un dégradé déterministe depuis le nom d'artiste via `artistToGradient()` dans `ColorUtils.kt` (HSL, saturation 30-40%, lightness 22-32%, jamais flashy) avec une icône `MusicNote` en overlay semi-transparent. Utilisé partout où `coverUrl.isBlank()`.

**Système de réactions** : `ReactionUtils.kt` (top-level, package `com.bughaxx.lastair`) contient `reactionDocId(from, to, trackName, artistName, friendTimestamp: Long): String` — SHA-256 des 5 champs avec `|` comme séparateur. ID déterministe pour upsert Firestore. `ReactionRepository` expose `sendReaction` (appelle `document(docId).set()`), `removeReaction(docId)` (appelle `.delete()`), `loadMyReactions(from): Map<String, String>` (retourne `Map<docId, emoji>`). `FriendsActivityViewModel` expose `myReactions: StateFlow<Map<String, String>>`, `sendReaction(...)` et `removeReaction(docId)`. Dans `HomeScreen` page 1, chaque item du `LazyColumn` calcule son `docId` et passe `myReaction = myReactions[docId]` à `TrackCardShowAll`. La `LazyColumn` utilise `key = { "${it.username}_${it.timestamp}" }` pour éviter les bugs de recyclage. `TrackCardShowAll` reçoit `myReaction: String?`, `onSendReaction: (String) -> Unit`, `onRemoveReaction: () -> Unit` — plus de `ReactionRepository` instancié dans le composable. Badge emoji animé (spring + shrink à la suppression) affiché en `BottomStart` du `Box` racine de la carte, en dehors du `if(myReaction != null && isVisible)` pour le `LaunchedEffect` qui remet `isVisible = true`. Règles Firestore : `reactions` — `allow read: if request.auth != null`, `allow create, update: if request.auth != null && request.resource.data.from is string`, `allow delete: if request.auth != null`.

**ShowAllScreen** : reçoit `type: String`, `navController`, `authViewModel`. `ShowAllViewModel` expose `items: StateFlow<List<MediaItem>>`, `period: StateFlow<String>` (défaut `"overall"`), `setPeriod(newPeriod, username, type)` qui vide `_items` avant de recharger (skeleton réapparaît). `MediaItem` a `name`, `subtitle`, `imageUrl`. `LazyVerticalGrid(GridCells.Fixed(2))` avec chips de période en `item(span=GridItemSpan(2))`, skeleton shimmer si `isLoading && items.isEmpty()`, `itemsIndexed` pour les cartes avec rang. `MediaItemCard` composable séparé avec `rank: Int`, dégradé vertical sur la cover, `GenerativeCover` si `imageUrl.isBlank()`. Endpoint `getTopTracks` ajouté dans `LastFmApi` avec `user.gettoptracks`. Data classes : `TopTracksResponse` → `TopTracks(track: List<LastFmTracks>)` — attention le champ JSON est `"track"` (singulier) pas `"tracks"`.

**Notifications** : deux canaux créés dans `MainActivity.createNotificationChannels()` — `"service_channel"` (`IMPORTANCE_MIN`, `setShowBadge(false)`, silencieux) et `"reactions_channel"` (`IMPORTANCE_DEFAULT`, `enableVibration(true)`). `ReactionListenerService` est un foreground service (`startForeground(1, notification)` avec `service_channel`). `onStartCommand` remet `listenerRegistration?.remove()` et `startTimestamp = Timestamp.now()` avant de relancer l'écoute pour éviter les listeners dupliqués (bug qui causait 4-6 notifications identiques). Filtre par `reactionTime > startTimestamp` pour ignorer les réactions existantes. Manifest : `android:foregroundServiceType="dataSync"`, permissions `POST_NOTIFICATIONS`, `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_DATA_SYNC`. Démarré depuis `HomeScreen` dans `LaunchedEffect(userProfile?.lastfmUsername)` avec `startForegroundService` sur Android 8+. `showReactionNotification` crée un `PendingIntent` vers `MainActivity` avec extra `"route" = Routes.INBOX` (`FLAG_UPDATE_CURRENT or FLAG_IMMUTABLE`).

**Points d'attention importants** : `reactionDocId` est dans le package `com.bughaxx.lastair` mais `HomeScreen.kt` est dans `com.bughaxx.lastair.ui.theme` — import explicite obligatoire. `@PropertyName` sur Firestore nécessite des `var` (pas `val`) dans les data classes. Le BOM Firebase gère les versions — pas de `version.ref` sur `firebase-auth` et `firebase-firestore` dans le TOML. Cache `CacheRepository` versionné avec `CACHE_VERSION = 2` — incrémenter quand le format des données change. `bestUrl()` extension sur `List<LastFmImage>` retourne l'URL Last.fm par priorité `mega > extralarge > large` — retournait des vraies URLs non-placeholder même en basse qualité, ce qui court-circuitait l'ancien `ItunesHelper` (bug corrigé en inversant la logique).

**Ce qui reste à faire / en cours** : crash au scroll dans le feed amis sur certains appareils (stacktrace pas encore récupéré), notifications de réactions à valider end-to-end après correction des listeners dupliqués, Option B des notifications (WorkManager "tes amis écoutent") non implémentée, wizard de création de profil Firestore non implémenté (photo de profil actuellement prise depuis `FirebaseAuth.currentUser?.photoUrl`).
